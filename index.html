Why we built it

One person runs about twenty software and research projects with AI agents doing most of the typing. The agents are good. What kept going wrong was everything around a single session:

  • They forget. Each session starts cold, so a lesson learned on Monday is re-derived on Thursday, sometimes wrongly.
  • They claim without proof. "Done" arrives before anything was run, and a confident wrong answer looks exactly like a right one.
  • Knowledge leaks. Notes, tickets and chat logs pile up in different tools, and the next agent cannot find what the last one knew.
  • Nobody checks that the checks ran. A green result over nothing is the most expensive bug there is.

Groundworks started as an engine for reading one very large record, where a database refused any conclusion that did not cite evidence. The same idea turned out to be what every project needed: a place where what agents learn is kept, cited and checked, and where the rules are enforced by the machine instead of remembered by the model.

The mascot is the foreman. He digs, keeps the ledger of what was found, tapes off dead ends so nobody falls in twice, and never calls a job done until he has seen the proof.

What it is now

One Rust binary, groundworks, and a Claude Code plugin around it. Your data lives in a private home folder next to your projects, never in the repository.

Registry

Every project, its stack, its environments, and where its secrets live. References only, never values.

Supervised store

A local SurrealDB, restarted if it dies, exported nightly and restore-drilled. Each agent signs in as its own user.

Intake

Files, docs and commits become citable units with file, lines, hash, date and expert area.

Evidence-gated journal

Decisions, gotchas and dead ends per project. CONFIRMED needs a receipt, a quote found word for word, or an owner statement.

Ask and answer

A packet of the best candidates, recorded facts first. Every quote in the answer is checked by a program, and a passed answer is recorded for next time.

Run and gate

Commands run in a project's registered environment and leave a receipt. The gate runs the project's own proof.

Team of experts

Architect, engineer, SRE and security roles plus your domain experts, with a directory that routes each question.

Hooks that run themselves

Session start injects what is known. A deny list guards the shell and fails closed. Stop asks a session that changed things to record what it learned.

Pulse

Is knowledge growing, used, and backed up? No model, just store numbers, and a digest of only what is red.

Selftest

A throwaway home and store, every rule checked both ways: 105 checks, each shown red before it is trusted green.

How we use it

Every Claude Code session runs with the plugin on, in VS Code and in the terminal. The loop is the same in every project:

  1. Session start. The hook names the project and injects what is already known, gotchas first.
  2. Ask before deriving. The agent asks Groundworks before it researches or rebuilds a conclusion.
  3. Work through receipts. Commands go through run, and changes are proved with gate.
  4. Record before stopping. Decisions, gotchas and dead ends go into the journal, tagged CONFIRMED, INFERRED or UNKNOWN.
  5. Unattended. The supervisor keeps the store up, exports it nightly, drills a restore and takes a pulse.
As of 30 October 2026: 18 projects, about 49,000 units, 155 live facts, nightly export and restore drill passing. The hooks went live on 29 October, so the usage numbers are days old, and the first digest says plainly that most of last week's commits happened outside a hooked session.

What is planned

A desktop window

A private build on Nimbalyst (MIT): sessions, chat, changes, and a Groundworks health tab, with the plugin and hooks pinned on.

Consult-first, forced

A hint on every prompt with what is already known, and a store lookup before web research or delegation.

Checks itself

Red conditions sent to a notification and a webhook, with a heartbeat elsewhere so a dead machine is noticed too.

Grow, then prune

The store may grow. One command removes a project and all its data, dry run first, exported and drilled before it deletes.

A fresh eval

A new question set drawn from real asks, and the window compared against VS Code on it.

Install

cargo install --path rust/crates/gw-mcp --locked
claude plugin marketplace add <path to the repository>
claude plugin install groundworks@groundworks
groundworks selftest

Then open a project in Claude Code and run /groundworks:init.
