| 2026-09-15 | **Vectors not adopted for search in instance 1 yet.** Bake-off (`xscholar/embed`) on 7,995 in-record units, 92 confirmed-fact queries: BM25 nDCG@10 .470 [.398,.549]; bge-m3 dense .255; Qwen3-Embedding-0.6B dense .183; RRF hybrid with bge-m3 .376. No model or hybrid cleared the keyword baseline. Keyword search stays the default; bge-m3 vectors are kept in a derived database for the next test | The fixed evaluator decides, not expectation. Caveat: 69 of 92 queries quote the record verbatim, which favors keyword search; on the 23 paraphrased queries recall was indistinguishable. Next test needs a paraphrase query set and the eliminated-claim use case |
| 2026-09-15 | **Reading layer built (`xscholar/present`) but the speedread view is NOT the default.** It stays behind `view=speedread`. Measured on three real documents: preservation 100%, check-first rows appear about 3x earlier, but reviewer catch rate was 4/15 (full) vs 3/15 (speedread), and **0 of 12 relabelling errors (status upgraded, verdict softened) were caught in either arm** | Presentation cannot surface an error that the text does not contradict. Adoption waits on v1.1 plus the inline gate re-check (C18) |
| 2026-09-15 | Relabelling errors are out of scope for presentation and belong to a mechanical re-check: re-run the promotion rule over rendered rows and show the result inline (C18) | Measured: no layout caught them; the datastore already answers the question in bulk |
| 2026-09-15 | **Inline rule re-check shipped (C18): a policy `rules` list, re-checked over every rendered row, a "Fails its own rule" section before Check first and a bold `RULE FAIL` marker inline; eliminated and superseded rows are exempt.** Measured on the three C17 documents (234/226/163 rows, 15 planted errors): status_upgrade 3/3 and verdict_soften 3/3 flagged, but only 4 of the 6 newly flagged by the plant; preservation stays 100% in every mode | The marker closes the relabelling gap only as far as the instance's declared rules reach: it re-checks labels against rules, it is not the datastore gate and it proves nothing about the evidence. A precise rule (established needs a locator) flagged 0 clean rows and exactly the planted upgrade; a rule the instance cannot satisfy yet (an answered attack links its answer) flagged a third of every document. **Reviewer round after tuning: 5/15 caught, 0 false alarms, but 0/3 status upgrades reported despite being flagged first in every document. Flag wording, not flag placement, is the open variable (C20); reconcilable section counts caught a relabel where prose did not** |
| 2026-09-15 | Panel consensus keeps the exact 2/3 default (owner); thresholds and confidence weights are owner settings held in a per-instance file and copied in at lock (`lock --settings`), which refuses a panel that disagrees. The bar stays strictly above 0.5; a two-medium majority on three seats carries only if the owner raises the medium weight | Instance 1 measured that no allowed bar lets two medium seats of three carry (1.5 is exactly half); a manual copy step caused the rounding bug |
| 2026-09-15 | MCP server as a front door over the typed core: generic engine server plus instance adapter; no raw query, delete or schema tools; server stamps provenance | Agents use the full system without bypassing gates or attribution |
| 2026-09-16 | **The graph shape is an instance's, not the engine's.** `instance.yaml` may declare `tables:` (extra node tables) and `edges:` (extra edge types, with `from`, `to` and typed/enumerated fields); the engine keeps `BUILT_IN_NODE_TABLES` and `BUILT_IN_EDGES` and everything downstream reads `inst.node_tables()` / `inst.edge_map()`. A declared name that collides with a built-in, or an edge end that is not a table, is refused by name at load time | The charter rule: fix the contract, not the instance. `authority` and `relies_on` are already domain leakage that reached engine code this way; eleven more were queued behind it (notes/2026-09-15_engine_gaps_from_instance_config.md). Declared and built-in are now the same code path -- schema, gates, probes both ways, PERMISSIONS, cleanup, the generated skills |
| 2026-09-16 | A recorded exception to a gate clause is an EDGE carrying a reason, not a boolean marker on the row being promoted | `gate_expression` ANDs its clauses and no clause can read a field of the row under test, so "preserved OR excused" is not expressible. Rather than add disjunction for one case, V2-8's exception is a `preserves` edge with `how: not_captured`: it has a unit behind it and a reason on it, and it is visible in the graph instead of being a flag someone set. Disjunction stays an open engine question (V2-17) |
| 2026-09-16 | The wrong-evidence probe is generated for any constrained clause whose field has a domain the engine knows, and REPORTED untested where it is not | It was keyed on the edge being named `cites` -- a domain word in engine code, and the reason V2-9's rule could not have been probed through config at all. "Reported, never skipped" is the same rule the forbidden-evidence probe already follows |
| 2026-09-16 | **Independent promotion** is `independent: true` on a gate rule. The datastore records every signed-in credential that wrote a row (`written_by`, a VALUE field over `$auth`) and a generated EVENT refuses the gated change from a credential on that record, from root, and on a row no credential has written. It is emitted with the gates, not with access, and config refuses it without an `access:` role that reads and writes the table | Measured on a real instance: 50 authorities promoted on one reading after the adversarial verifier died. The evidence gate checks evidence exists, not that anyone independent looked. Not a gate clause: the check compares the writer with a field of the row under test, which no clause can read. Not a field ASSERT: it sees the field's previous value, not the previous row. An event sees `$before`, `$after` and `$auth`, and a THROW aborts the write. `author` is caller-supplied and proves nothing; a caller's SET of `written_by` is discarded (measured, agent and root). Root has no `$auth`, so root can never promote; root can still provision credentials or redefine the event, which is the datastore owner acting deliberately. Probed both ways with two provisioned credentials; reported untested by name when they cannot be built. notes/2026-09-16_independent_promotion_and_unique.md |
| 2026-09-16 | **Uniqueness** is a top-level `unique: {table: [field, ...]}`, one UNIQUE index per field, for built-in and declared node tables; a field the table does not have is refused by name; `unique` is human-owned when present; the baseline pins it | One section covers built-in tables, which have no `tables:` block to hang a key on. Measured on 3.1.6: duplicates refused on CREATE/UPDATE/UPSERT for root and record users, exact comparison (case and whitespace count), any number of NONE in an optional field, and defining the index over existing duplicates is refused with no index left behind. Single-field only; composite keys are not built |
| 2026-09-16 | **Live-schema drift** (`xscholar/live_schema.py`): the live database's definitions are compared by name (missing / altered / unexpected) with the config's, where the expected side is rendered by the SAME server into a scratch database and removed afterwards | Nothing caught a rule removed by hand while the config still had it. Measured on 3.1.6: INFO rewrites every definition (`IN`→`INSIDE`, `option<T>`→`none \| T`, `7d`→`1w`, added `PERMISSIONS FULL` and sub-fields), so text comparison flags everything; two databases given the same statements render byte-identical INFO, so same-server rendering compares exactly. Password hashes, which INFO returns in full, are replaced by a digest at read time. Proven on nine hand edits and a schema re-applied after access. Sees schema only: not data, not an import, not a change undone between runs. notes/2026-09-16_live_schema_and_promotion_audit.md |
| 2026-09-16 | **Independence between principals and the promoter's own evidence** are the mapping form `independent: {between: principal, own_evidence: true}`; `true` is unchanged. Principals are declared at provisioning (`agent.principal`) and copied onto `row_writer` when a row is written; link creators are recorded on CREATE in `link_creator`; both by privileged events into tables no credential can write | Measured: VALUE clauses run with the writer's permissions (cannot read the agent row) while events run privileged; `written_by` on an edge lets a promoter "own" a link by touching it, so only creation counts; relation `in`/`out` cannot be re-pointed. A principal is what the provisioner declared; own evidence proves a link was created, not that its source was read. Bearer grants measured and not adopted: the token is refused over HTTP |
| 2026-09-16 | **Every gate rule is also a privileged event** (`<rule>_gate`), beside its ASSERT | Reproduced from the coordinating session: an ASSERT's subqueries run under the caller's row permissions, so a credential that cannot read the forbidden rows passed a forbids clause. The event refused it. A requires clause still refuses a caller blind to the evidence (fails closed); dropping the clauses from the ASSERT is left to the owner. Probed with a blind credential when a role is blind to a forbids clause |
| 2026-09-16 | **Promotion log** (`promotion_log: true`, human-owned when present): a hash-chained, append-only record of every gated promotion written by an event, verified outside the datastore, anchored by an exported head; `late` flags a promoter provisioned after a writer first wrote the row (heuristic, never blocking) | Measured: 60 concurrent promotions on memory, rocksdb and surrealkv never forked (a single contended head record; losers get retryable conflicts and do not happen). Root can rebuild the whole chain and it verifies; only an anchor kept off the database host catches that, which a test asserts |
| 2026-09-16 | **Built-in field definitions are data** (`gates.builtin_schema`): the schema renders them and a gate on a built-in field restates the field's type, default and own ASSERT from the same entry; a gate on a field that is neither built in nor declared refuses to generate | A gate is a `DEFINE FIELD OVERWRITE` applied after the schema. A second, hand-written restatement for built-ins dropped `unit.status` / `unit.grade`'s config lists (V2-22(a)); b52ea90 had fixed the declared path only. One source for both readers; demo schema and gate text byte-identical before and after |
| 2026-09-16 | **One answer per critique, revisable, with history** | `Writer.answer` UPSERTs `answer:ans_<critique>` with a deterministic edge id; `text_history` on answer is append-only and event-written, like `verdict_history`. A downgraded head must be answerable again (V2-22(f)), and a `damaging` head is released by its answer, so what the answer said before belongs on the record. Left out of `temporal.snapshot`, which counts rows by value |
| 2026-09-16 | **Gate probes run where they can mean something** (`gates.run_probes_where_they_can_run`): on a database that already enforces originals, the gates are probed in a scratch database on the same server with the same generated definitions (and access, when applied), removed afterwards; `scripts/run_instance.py` probes again after access is applied | Probe units carry no originals, so enforcement would refuse every accept for the wrong reason. Before access, every writer is a system user, so the blind-caller probe (V2-21) could never run in the demo. One implementation for the runner and `gates --apply` |
| 2026-09-16 | **One throwaway-server start** (`surreal_bin.start_memory`); the demo runner and the evaluator call it | docs/TUNING.md third lane rule. The evaluator held a copy of the runner's guards; a later fix to one would have missed the other |
| 2026-09-16 | **MCP `health` never reports a check it could not run as 0**: live-schema drift, the promotion log (with `late`), assertion contradictions and the originals gap each report a count that can show a problem, `NOT_EXECUTED` with the reason under an agent credential, or `off` / `none declared` | CLAUDE.md rule 5. Measured: `originals.health` raised on `INFO FOR TABLE` under a record credential, so the whole health call failed for an agent-launched server |
| 2026-09-16 | **The MCP server refuses every write from engine code it cannot show is a verified, current commit** (`xscholar/mcp/code_state.py`): off `main`, uncommitted changes (tracked anywhere, untracked under `xscholar/`), the checkout moved since startup (STALE), or the state unreadable (UNKNOWN) -> `rejected_by_gate` naming the cure. Git is re-read before every write, unthrottled. Not a git checkout is UNKNOWN and refused. `XSCHOLAR_ALLOW_UNVERIFIED=1` lets writes through and `health` leads with a WARNING | Real use: a live server served write tools from a WIP branch and kept the code in memory after the checkout was switched back. UNKNOWN is refused because the guard exists to show a reviewed commit and a copy without history cannot; a deliberate non-git deployment uses the override and wears the warning. Untracked files outside the package are not code the server imports. Measured 71-88 ms per read on Windows (two git processes); writes are agent-paced and a throttle would reopen the window. notes/2026-09-16_mcp_real_use.md |
| 2026-09-16 | **`health` leads with `engine_code` and a summary derived mechanically from the adapter's detail** (every NOT_EXECUTED key or string, false `ok`/`passed`/`verified`/`clean`/`valid`, every drift-named number, non-zero counts, list lengths with five names); `detail=false` drops the detail; the default keeps it | Real use: about 60 KB, the number that mattered buried. Derived rather than adapter-supplied so a summary cannot hide what the detail says; a randomized planted-problem test holds it to that |
| 2026-09-16 | **Generic adapter health counts carry a WHERE and know the credential's role** (`XSCHOLAR_ROLE` when `XSCHOLAR_DB_ACCESS` is set): a table the role cannot read is `NOT_EXECUTED`, and a zero under a record credential of unknown role is `NOT_EXECUTED` | Measured on SurrealDB 3.1.6: `SELECT count() AS n FROM unit GROUP ALL` answers 0 to a record credential that reads the row, 1 with `WHERE true`; root sees 1 either way, which is why no root-run test saw it. `originals.health` and `lens.lens_view` carried the same query on the MCP path and were changed the same way. `db.count`, `lens.view_counts` and `assertions` still use the unfiltered form (root callers today) |
| 2026-09-16 | **Adapter conformance is checked by calling the adapter** (`python -m xscholar.mcp.conformance`), read-only by default; writes need `--write --scratch NS/DB` equal to the adapter's own database | Real use: an adapter written before b52ea90 "still answers" and nobody could tell whether it degraded. Shapes are tied to adapter.py's docstrings by a test |
