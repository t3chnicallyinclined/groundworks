What this is

I'm a cloud engineer, not a software company. I have a lot of research and side projects going, and I use AI agents (mostly Claude Code) to help with them. I made Groundworks to make my own life easier on that work. It's a personal project, and I'm sharing it in case it's useful to someone else.

What I'm trying to fix

  • Every new agent session forgets what the last one figured out, so the same lessons get re-learned.
  • Agents sometimes say something is done or fixed before anything was actually run.
  • Notes end up scattered across files, chats and tickets, and the next session can't find them.

The mascot is the foreman. He digs, keeps a ledger of what was found, and tapes off the dead ends so nobody falls in twice.

What it does

A small Rust program plus a Claude Code plugin. It keeps a local database next to my projects and gives the agent a few tools and habits.

A journal per project

Decisions, gotchas and dead ends get written down. Anything marked confirmed has to point at proof: a command that ran, or a quote from a file. Text that looks like a secret is refused.

Search over my projects

Files, docs and commits are indexed so the agent can look things up before re-deriving them. Quotes are checked against the source.

Receipts

Commands and build checks run through Groundworks and leave a record.

Hooks

A session starts with that project's notes, even in a git worktree. Risky shell commands and edits to Groundworks' own guard files are blocked. A session that changed things can't stop until it writes down what it learned.

Housekeeping

A supervisor keeps the database running, backs it up nightly and test-restores the backup. A short health report shows whether things are healthy, including work Groundworks didn't see.

Stays local

Your notes and data live in your own folder on your machine, never in the repo.

How it works: the whole harness

Groundworks is less one tool and more a harness around each agent session.

Your projects
code, docs, commits
intake →
The store
a local graph: fact → evidence → source lines, fact → receipt
← look up, record, run →
Claude Code + plugin
hooks, tools, expert agents
  1. A home folder next to my projects holds the registry (projects, environments, and where secrets live, by reference only), the expert agents, and the database.
  2. Intake reads each project's code, docs and commits into small citable pieces called units, each with file, lines, hash and date.
  3. The store is a local SurrealDB graph. A fact is linked by an evidence edge to the exact units behind it, or to the receipt of the command that proved it. Each project's data is kept in its own section of the database, so it's easy to find, and later to remove.
  4. The agent works through tools: look things up before re-deriving them, use run and gate to do and check work, and write to the journal to record what it learned.
  5. The hooks make that happen without counting on the agent to remember: notes in at the start, a guard on the shell and on Groundworks' own files, and a stop that waits until something is recorded.
  6. The supervisor keeps the database running, backs it up nightly, test-restores the backup, and writes a short health report.

A few choices I made

There are plenty of good agent memory tools out there, and I'm not claiming this one is better. I built it for my own research and projects, and these are the choices that fit how I work:

The database holds the line

Marking a fact as confirmed needs a link to real source, a command receipt, or my say-so. Without one, SurrealDB refuses the write.

A program checks quotes

When an answer cites a file, the quote has to be found word for word in what the agent actually read.

Dead ends are kept

Ruled-out approaches are written down with the reason, so they don't get re-tried.

Facts link to their proof

Because it's a graph, I can walk from a fact to the lines or command behind it.

Each agent signs in as itself

So I can see who wrote what.

Organised by project

One home covers all my projects. Related ones can see each other, private ones can be walled off.

Kept simple

One local program and one local database. No cloud service, and no AI model inside Groundworks itself.

How I use it

Most of my Claude Code sessions run with the plugin on. In practice it's simple: the agent starts with what's already known, looks things up before guessing, and leaves notes for next time. It's early, it changes often, and some parts are rough.

Try it

You need Rust (stable, via rustup), SurrealDB 3.x on your PATH (built and tested on 3.1.6), Git, and Claude Code.

# 1. Build the program
cargo install --path rust/crates/gw-mcp --locked

# 2. Make a home folder next to your projects
mkdir -p ~/projects/.groundworks
echo 'workspace = "/home/you/projects"' > ~/projects/.groundworks/groundworks.toml

# 3. Start the store and create your owner login, once
#    (type the password yourself; Groundworks never stores it)
export GROUNDWORKS_OWNER_PASS=...
cd ~/projects && groundworks store init
unset GROUNDWORKS_OWNER_PASS

# 4. Add the plugin to Claude Code
claude plugin marketplace add <path to the repository>
claude plugin install groundworks@groundworks

# 5. Check it
groundworks selftest
groundworks doctor

Then open one of your projects in Claude Code and run /groundworks:init.

If it sounds helpful, give it a fork and make it fit how you work. Issues and ideas are welcome.
